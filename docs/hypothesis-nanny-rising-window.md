# Предзаявленная гипотеза: нянька в растущем окне

**Записано: 2026-08-07, ДО получения результатов нового окна.**
Файл фиксирует правила трактовки заранее, чтобы после прогона нельзя было
подкрутить критерий под то, что получилось.

---

## Что проверяем

Утверждение под проверкой: **«эдж adopt-няньки — в сопровождении позиции
(стоп/BE/трейл), а не в направлении рынка».**

Прошлый прогон (окно 2026-07-18 → 2026-08-03, 5m, n=11 259) дал парную разницу
«мои правила − их выход» **+0.167%** на сделку, 95% CI [0.101; 0.233],
pessimistic. Эффект держался и в optimistic: +0.120%, CI [0.054; 0.185].

Проблема: то окно — **−2.1% по BTC**. Эффект мог быть не эджем сопровождения, а
структурным перекосом (нянька режет лонги стопом раньше, чем их режет рынок).
Если так — в растущем окне эффект должен исчезнуть или сменить знак.

## Дизайн

| | |
|---|---|
| Тестовое окно (растущее) | **2026-06-28 → 2026-07-14, BTC +9.2%** |
| Контрольное окно (боковик) | **2026-07-18 → 2026-08-03, BTC −2.1%** |
| Пересечение окон | **нет** (14.07 < 18.07) — чистый out-of-sample |
| Интервал свечей | **15m в обоих окнах** |
| Горизонт удержания | 72 ч |
| Правила выхода | из `strategistAdopt.js`: стоп ATR(1h,14)×1.5 в [2%,8%] (фолбэк 5%), BE-храповик при пике ≥1.5% → выход в 0%, трейл при пике ≥2% → откат 30% |
| Комиссия | 4.5 бп на сторону |
| Отбор адресов | механически по месячному обороту $50k–$5M, **без взгляда на PnL** |

**Почему 15m, а не 5m:** HL отдаёт ~5000 свечей на интервал. 5m = 17.4 дня
назад, растущее окно туда не попадает. 15m = 52 дня, попадает. Контрольное окно
поэтому **перепрогоняется на 15m тоже** — сравнивать прогоны на разных
интервалах нельзя, тайминг срабатывания правил зависит от размера бара.

**Первичная метрика:** парная разница `мои правила − их собственный выход`,
net% на сделку, на одних и тех же входах. Считается в обоих режимах вилки
(pessimistic / optimistic по неизвестному внутрибарному порядку).

**Вторичные:** сравнение со случайным выходом (бейзлайн); разрез long / short.

## Решающее правило (зафиксировано заранее)

Пусть `d_test` — парная разница в растущем окне.

1. **ЭДЖ ПОДТВЕРЖДЁН** — если нижняя граница 95% CI `d_test` > 0 **в обоих**
   режимах вилки **и** на полной выборке (не только на лонгах).
   → Нянька добавляет поверх чужого выхода независимо от режима рынка.

2. **ЭДЖ ОПРОВЕРГНУТ (это была бета)** — если CI накрывает ноль **или** среднее
   отрицательное.
   → Прошлый результат объясняется падающим/боковым рынком. Дверь закрыта,
   в adopt как в источник эджа больше не вкладываемся.

3. **НЕ ПОДТВЕРЖДЁН, зависит от режима** — если эффект > 0 только в одном режиме
   вилки, или только на одной стороне (long/short), или знак совпадает, но CI
   задевает ноль.
   → Трактуем как **отрицательный** результат для практических целей: торговать
   на этом нельзя. Записываем как «работает только при условии X», не более.

**Заранее запрещено:** менять окно, интервал, горизонт, фильтр адресов или
набор монет после того, как увидели результат. Если что-то из этого меняется —
это новый эксперимент с новой записью, а не уточнение этого.

## Что этот тест НЕ докажет даже при исходе (1)

- **Survivorship по адресам.** Снимок лидерборда один — 2026-08-03. Адреса
  отобраны по обороту, не по PnL, но сам факт присутствия в снимке означает
  «дожил до августа». Для окна конца июня это смещение порядка 5 недель.
- **Внутрибарный порядок неизвестен** — отсюда вилка. Если вывод меняет знак
  внутри вилки, вывода нет.
- **Проскальзывание не смоделировано.** Выход считается по цене уровня; в
  реальности стоп/трейл исполняются хуже. Эффект +0.15% сопоставим по порядку
  с проскальзыванием, и это отдельный риск для любого практического вывода.
- **Одно растущее окно — это n=1 по режимам.** Два окна не дают вывода
  «работает во всех режимах», только «не развалилось на втором».

## Результат

Прогон 2026-08-07, оба окна на 15m.

| Окно | режим BTC | n | pess. разница + CI | opt. разница + CI |
|---|---|---|---|---|
| 2026-07-18 → 08-03 | −2.1% | 11 259 | **+0.222%** [0.156; 0.288] | **+0.146%** [0.081; 0.212] |
| 2026-06-28 → 07-14 | **+9.2%** | 12 715 | **+0.143%** [0.078; 0.208] | **−0.005%** [−0.066; 0.057] |

**Исход по решающему правилу: пункт 3 → трактуется как отрицательный.**
В растущем окне optimistic-ветвь вилки накрывает ноль. Вывод меняет знак внутри
вилки — значит вывода нет, как и было записано заранее.

### Механизм: разрез long/short даёт полную инверсию

| Окно | сторона | pess. разница | opt. разница |
|---|---|---|---|
| −2.1% (боковик) | **long** | **+0.357%** [0.267; 0.446] | **+0.285%** [0.197; 0.374] |
| −2.1% (боковик) | short | +0.042% [−0.057; 0.141] | −0.039% [−0.136; 0.058] |
| **+9.2% (рост)** | long | −0.030% [−0.115; 0.054] | **−0.188%** [−0.271; −0.105] |
| **+9.2% (рост)** | **short** | **+0.352%** [0.252; 0.451] | **+0.216%** [0.125; 0.307] |

Эффект **полностью меняет сторону вместе с режимом рынка**: в боковике/падении
он на лонгах, в росте — на шортах. На обеих сторонах одновременно его нет
никогда.

### Объяснение

Нянька держит позицию **в 3–5 раз дольше** входившего (434 против 87 мин в
контрольном окне, 319 против 100 в тестовом). Долгое удержание = больше
экспозиции к тренду. Её стоп механически обрезает ту сторону, которая идёт
против рынка, и даёт додержать ту, которая идёт по рынку.

Поэтому «эдж» появляется ровно на той стороне, которая в этом окне была
неправильной. **Это бета, а не эдж сопровождения.** Чтобы им пользоваться, надо
заранее знать направление рынка — но если знать направление, нянька не нужна.

**Гипотеза «эдж в сопровождении, а не в направлении» — опровергнута.**
В adopt как в источник эджа больше не вкладываемся.
