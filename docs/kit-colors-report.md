# Цвета витрины через токены кита

## Результат

Сырые цвета в области проверки устранены: `node scripts/checkRawColors.mjs`
показывает долг `0`. Сторож добавлен в `npm run guards`; `--update` записывает
только уменьшившуюся планку. Исключены только `src/dev/` и файл определений
локальных токенов; последний теперь тоже ссылается на палитру `--color-*` кита.

Механическая замена выполнена `scripts/migrateRawColors.mjs`; скрипт остаётся
в истории, повторный запуск идемпотентен.

## Сырой цвет → токен

| Группа исходных цветов | Замена |
| --- | --- |
| зелёные PnL и положительные состояния | `--gain`, `--gain-wash`, `--gain-line` |
| красные ошибки и отрицательные состояния | `--loss`, `--loss-wash`, `--loss-line` |
| янтарные предупреждения и EMA | `--caution`, `--attn`, `--plot-ema` |
| синие и фиолетовые акценты | `--accent`, `--accent-2`, `--wash` |
| белый текст на цветной заливке | `--accent-ink` |
| серые поверхности, текст и линии | `--panel*`, `--ink*`, `--rule*`, `--plot-grid` |
| прозрачные варианты | `color-mix()` от соответствующего токена |

Созданные локальные токены не добавлялись: существующие `--pnl-*`, брендовые,
tier и skeleton-токены сохранены, но теперь определяются через палитру кита.

## Визуальная сеть

Старая сеть признана недействительной и её PNG больше не являются эталонами:
она снимала исходники Vite, отдавала API пустой объект и поэтому фиксировала
пустые страницы либо overlay ошибки.

`scripts/snapshotDash.mjs` теперь сначала вызывает `npm run build:dash` и
отдаёт только `src/modules/dashboard/dist` с локального HTTP-сервера. Для
страниц подставляются детерминированные ответы API с ценовыми рядами, таблицами,
карточками и графиками; WebSocket отключён. До сохранения кадра скрипт валит
прогон при overlay Vite, фоне body не из `--ground`, отсутствии стилизованной
разметки или менее чем 50 цветах.

Команда для baseline: `KIT_COLORS_PORT=4175 node scripts/snapshotDash.mjs
docs/kit-colors/before --project /путь/к/worktree-main)`. Для ветки:
`node scripts/snapshotDash.mjs docs/kit-colors/after --twice`; одинаковые
`run-1` и `run-2` — обязательное условие перед `compare -metric AE -fuzz 2%`.

Финальные эталоны, AE-таблица и три склейки пока не обновлены: в текущем
исполнительном окружении Chromium зависает на первом рендере `index` до
сохранения кадра. Это не маскируется нулевыми числами; нужен успешный прогон
у оператора после снятия ограничения среды.
