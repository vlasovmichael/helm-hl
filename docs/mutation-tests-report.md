## Выжившие мутанты

### `executor/math.js`

Остались 14 мутантов на пограничных значениях `formatHlPrice`, минимального
размера и вычисления комиссии. Они не эквивалентны; для достижения 100% нужны
дополнительные отдельные сценарии границ.

### `executor/fill-parser.js`

Осталось 6 мутантов:

- `fill-parser.js:27`, `ok: false → true` для пустого статуса: флаг `ok` уже
  не используется вызывающим кодом при наличии диагностической ошибки; изменение
  наблюдаемо только для клиентов, которые одновременно игнорируют `error`.
- `fill-parser.js:28`, удаление `.slice(0, 300)`: эквивалентно на коротких
  ответах; длинный ответ нужен лишь для ограничения диагностического лога.
- `fill-parser.js:60`, удаление `.slice(0, 200)`: эквивалентно на коротком
  неизвестном статусе; разница только в длине диагностического текста.
- `fill-parser.js:88` (три мутации `typeof`/optional chain): контракт universe
  допускает только объекты `{ name, szDecimals }`; строка или объект без `name`
  ломают `findAsset` раньше этой диагностической ветки, поэтому такие варианты
  недостижимы без изменения продового контракта.

### `executor/sizing.js`

Цель 90% недостижима без изменения продовой валидации входа: остались 10
мутаций, из которых шесть на `sizing.js:48` эквивалентны — последующий
`Math.max(0, margin * leverage)` всё равно возвращает `0` для нулевых и
отрицательных `free`/`equity`. Четыре на `sizing.js:78` меняют проверку
дистанции стопа только для `sl === price`: `calcRiskSize` затем сам возвращает
нулевой size как `tooSmall`; публичный контракт `resolveEntrySize` не определяет
такой стоп как исполнимый вход. Все наблюдаемые режимы (balance, risk, shadow,
cap и невалидный SL) покрыты тестами. Итоговый реальный балл — 84.13%.

### `executor/triggers.js`

Две выжившие мутации на `:30` и `:35` убирают ограничение длины JSON в тексте
ошибки. Для коротких ответов они эквивалентны; длинный ответ меняет только
объём диагностического сообщения, не вызов биржи и не защитный ордер.

### `executor/limitClose.js`

Остались 22 выживших мутанта и один timeout:

- `:28` — удаление `sleep(ms)`: при нулевом/минимальном тестовом ожидании
  результат сделки не меняется; различается лишь планирование event loop.
- `:33–36` — подстановка массива-маркера, пустой строки и снятие optional
  chain при чтении позиции. Для контракта `getPositions()` допустимы только
  массивы объектов `position`; невалидные варианты либо дают тот же `0`, либо
  завершаются тем же защитным «нет позиции» путём.
- `:43–44` — снятие optional chain у корня стакана. Биржевой контракт всегда
  возвращает объект book; `null`/`undefined` — транспортная ошибка до этого
  слоя, поэтому новый исходящий ордер не возникает.
- `:59–72` — маркер вместо пустых fills, текстовый coin и пустые объектные
  возвраты. При пустом или чужом наборе fills итоговая форма намеренно берёт
  `startSz` и пассивную цену; эти изменения не меняют наблюдаемый close.
- `:116–131` — снятие optional chain у сырого ответа limit-ордера. Ошибка
  разбора ловится тем же `catch` и переводит закрытие в обязательный market
  fallback; для валидных `filled`/`resting` ответов тесты убивают мутации.
- `:134` — подстановка непустокой строки вместо fallback `''`: у `Error`
  всегда есть `message`, поэтому регулярное выражение получает тот же текст.
- `:142`, `Date.now() >= deadline` — timeout: инвертированная граница может
  бесконечно продлевать polling при неподвижном тестовом времени. В боевом
  времени это не эквивалентно, но runner останавливает его как зависший.

### `targetTrail.js`

Остались 23 мутанта:

- `:21`, `:29`, `:80`, `:116`, `:121` — проверки невалидных нулевых/нечисловых
  входов. Тесты покрывают рабочий контракт с положительными ценами; отличия на
  невалидных данных не достигаются через публичный путь трейла.
- `:58` — удаление текста причины `ARM`; действие и передача защитного ордера
  не меняются, различается только диагностическое сообщение.
- `:124`, `:128`, `:130` — граница равенства stop/цены и альтернативные расчёты
  текущего R. Эти сценарии не дают нового допустимого движения стопа: при
  равенстве шаг нулевой, а исполнимые long/short движения проверены тестами.

### `dailyRisk.js`

Остались 9 мутантов:

- `:42–45` — замена пустого значения на пустую строку при `parseFloat`, а также
  добавочный элемент к пустому массиву; все варианты дают тот же нулевой вклад
  в итог дневных fills. Optional chain на `f` наблюдаем только с `null` в
  массиве, но такой вход штатно отфильтрован источником fills.
- `:92`, `:95` — безусловная запись уже совпадающего ключа дня не меняет
  результат следующего вызова.
- `:114` — удаление текста диагностического debug-лога при ошибке источника;
  fail-soft ответ и защита от входа не меняются.
- `:125` — удаление тестового экспортного reset-хелпера; в продовом пути он не
  вызывается.

### `positionNanny.js`

Остались 58 мутантов. Большинство относятся к необязательным полям сырого
ответа биржи (`null`-ордеры и пустой `orderType`), диагностическим строкам и
граничным случаям, которые не дают нового допустимого плана (например, цель на
текущей цене). Рабочие сценарии — long/short, стоп, цель, частичное покрытие,
нечитаемые ордера, сортировка и денежные расчёты — проверены поведением.

### `executor/state.js`

Остались 57 мутантов и четыре timeout. Это главным образом диагностические
логи и защитная толерантность к повреждённому persisted state (`:137–167`,
`:214–240`), а также два timeout при удалении `shift()` из очистки circuit
breaker (`:185`, `:252`): без очистки мутант бесконечно крутит цикл. Добавлены
наблюдаемые границы TTL, backoff и восстановления; продовый код не менялся.
