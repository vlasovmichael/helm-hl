# Задача: цвета витрины — только через токены @flwls/ui

Ветка `codex/kit-colors`, worktree `~/michaels_projects/hl-paper-scanner-codex`.
Без push, без merge в `main`, без деплоя. Порядок работы — `docs/REFACTORING.md`
(сеть до касания, шаг = один коммит = один revert).

## Контекст

Витрина: `src/modules/dashboard/web`. Кит `@flwls/ui` 0.5.0 уже подключён,
старые имена токенов запрещены `tests/kitTokens.test.js`. Аудит соответствия
токенов — `docs/design-system-audit.md`. Каталог токенов —
`node_modules/@flwls/ui/dist/tokens.css`.

Осталось ~137 сырых цветов (`#hex`, `rgb()`, `rgba()`, `hsl()`, `oklch()`) в
`web/src/styles/**` и ~37 в JS: `charts/levelsChart.js`, `charts/oiChart.js`,
`charts/simChart.js`, `features/accountStatus.js`, `features/calibrator.js`,
`utils/format.js`. Больше всего в `core/_tokens.scss` (свой слой: бренд, pnl,
tier, радиусы) и `features/_signals.scss`.

## Что сделать

1. **Сеть до касания.** Playwright-снимки всех страниц витрины (`*.html` в
   `web/`) в light и dark, 390 и 1280 px, через `npm run dev:dash`.
   - НЕ запускать `npm start` и `src/index.js`: это живой торговый бот с ключами.
   - API и WS — фикстуры через `page.route` / заглушку; данные и часы заморожены
     (`page.clock`), анимации выключены. Один и тот же прогон должен давать
     попиксельно одинаковые снимки — проверь это двумя прогонами подряд ДО правок.
   - Снимки «до» сохранить как эталоны; они и есть сеть.
2. **Сторож-храповик** `scripts/checkRawColors.mjs`, добавить в `scripts/guards.mjs`:
   считает сырые цвета пофайлово в `web/src/**/*.{scss,css,js}` и `web/*.js`,
   долг в `scripts/raw-color-debt.json`, рост в любом файле валит, `--update`
   переписывает долг вниз. Образец — `scripts/checkComments.mjs`.
   Исключения только явные: `dev/` (моки) и файл определений своих токенов.
3. **Замена.** Сырой цвет → ближайший семантический токен кита. Если у кита нет
   смысла (pnl, tier, бренд биржи) — один свой токен в `core/_tokens.scss`,
   определённый через палитру кита `--color-*`, с light и dark. Новых имён не
   плодить: перед созданием проверить, нет ли уже такого в ките или в
   `_tokens.scss`. В JS-графиках цвета читать из CSS-переменных
   (`getComputedStyle`), не дублировать значения; графики должны
   перекрашиваться при смене темы, как сейчас.
4. Компоненты кита (`h-select`, `h-dialog` и др.) НЕ подключать, разметку не
   менять. Только цвета.

## Приёмка

- `npm run verify` зелёный на каждом коммите.
- Сырых цветов вне исключений — 0, долг в `raw-color-debt.json` пуст.
- Снимки «после» сравнены с «до» попиксельно (`compare -metric AE -fuzz 2%`
  или pixelmatch). Каждая пара с ненулевой разницей — в отчёте строкой:
  страница, тема, ширина, число пикселей, что изменилось и почему.
  Слово «расхождений нет» без таблицы чисел отчётом не считается.
  Размеры снимков «до» и «после» должны совпадать; если нет — это находка.
- Отличие больше ~0.5% пикселей на странице без объяснения «цвет X стал
  токеном Y со значением Z» — откатить шаг, не обновлять эталон.
