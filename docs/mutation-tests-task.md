# Задача: тесты денежных модулей, проверенные мутациями

Ветка `codex/mutation-tests`, worktree `~/michaels_projects/hl-paper-scanner-codex2`.
Без push, без merge, без деплоя. Это живой торговый бот.

## Цель

Покрытие строк ничего не говорит: тест может пройти строку и ничего не проверить.
Мерило — мутационный балл (Stryker): сколько искусственно внесённых ошибок
(`<` → `<=`, `+` → `-`, удалённый вызов, `true` → `false`) ловят тесты.

Модули, по убыванию важности (здесь считаются деньги, размеры, стопы, закрытия):

1. `src/modules/executor/math.js`, `sizing.js`, `fill-parser.js`
2. `src/modules/executor/close.js`, `limitClose.js`, `triggers.js`
3. `src/modules/dailyRisk.js`, `targetTrail.js`, `positionNanny.js`
4. `src/modules/executor/reconciler.js`, `state.js`

## Порядок

1. Подключить Stryker как devDependency (`@stryker-mutator/core`, command runner
   поверх `NODE_ENV=test node --test`, или подходящий раннер). Скрипт
   `npm run mutation` с аргументом-модулем. В `npm test` и `verify` не включать:
   долго.
2. Замер «до» по каждому модулю: балл, убитые/выжившие/без покрытия. Таблица в отчёт.
3. Дописывать тесты, пока балл модуля не станет ≥ 80% (для групп 1–2 цель 90%).
   Каждый выживший мутант после работы — в отчёт строкой: файл:строка, мутация,
   почему не убит (эквивалентный мутант / недостижимо без сети / не успел).
   «Эквивалентный» — только с объяснением, почему поведение не меняется.
4. Шаг = один модуль = один коммит: тесты + обновлённая строка таблицы.

## Запреты

- Продовый код не менять. Если тест вскрыл баг — НЕ чинить: тест с
  `test.todo`/`skip` и подробное описание в разделе «Найденные баги» отчёта
  (вход, ожидание, факт, чем грозит в деньгах).
- Без сети и ключей: биржу, HL API, БД — моками/фейками, как в существующих
  тестах `tests/`. Не запускать `npm start`.
- Тесты проверяют поведение (вход → выход/вызов), а не детали реализации;
  не снапшотить объекты целиком ради убийства мутантов.
- Не ослаблять и не удалять существующие тесты.
- `npm run verify` зелёный на каждом коммите.

## Отчёт

`docs/mutation-tests-report.md`, закоммичен: таблица до/после по модулям
(балл, killed, survived, no coverage, время прогона), выжившие мутанты,
найденные баги, команда для воспроизведения замера одного модуля.
Оператор перезапустит замер на 2 модулях сам — числа должны совпасть.
