# Доработка: визуальная сеть не работала

Проверка оператора показала: эталоны в `docs/kit-colors/` пустые. `index-*` — один
цвет на весь кадр; `levels-*` — HTML без CSS; `login-*` — оверлей ошибки Vite
(`login.html: Failed to parse source for import analysis`). Светлая и тёмная тема
совпадают побайтно. Нули в таблице сверки ничего не доказывают, замена цветов
не проверена.

## Что сделать

1. Починить сеть. Снимать собранную витрину (`npm run build:dash` + статика из
   `src/modules/dashboard/dist`, как в проде у Express) или dev-сервер без ошибок.
   Фикстуры API/WS должны давать страницам реальные данные: таблицы, графики, карточки.
2. Сторож самой сети, в том же спеке, валит прогон, если для любого снимка:
   меньше 50 различных цветов; светлая и тёмная тема совпадают; в DOM есть
   `vite-error-overlay`; `getComputedStyle(body).backgroundColor` не равен
   значению `--ground` кита; на странице нет ни одного элемента с классом из её scss.
3. Снять эталоны «до» на `main` (коммит a3ac380, через `git worktree` или
   `git stash` твоих правок), убедиться в детерминизме (два прогона = 0 px).
4. Сравнить с текущей веткой. Каждая ненулевая пара — строкой в отчёте с
   объяснением «цвет X → токен Y». Необъяснимое — чинить в коде, не в эталоне.
5. Разбить работу на шаги по `docs/REFACTORING.md`: сеть, сторож, затем цвета
   порциями (по одному-двум scss-файлам или одному графику на коммит).
   Перепиши историю ветки интерактивно не надо — достаточно новых коммитов
   поверх; но шаги дальше — мелкие.
6. Приложить в отчёт 3 склейки до/после (index dark 1280, levels light 1280,
   graph страницы oi dark 390) — оператор проверит их глазами.

Отчёт обновить в `docs/kit-colors-report.md`, раздел «Визуальная сеть» переписать
целиком. Без push.
