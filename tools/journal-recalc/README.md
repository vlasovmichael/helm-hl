# journal-recalc — пересчёт дискреционного журнала

Скрипты пересчёта от 26.07.2026. Выводы — в `docs/journal-decomposition-2026-07-16.md`,
раздел «ПЕРЕСЧЁТ 26.07.2026».

## Данные

`history_archive.json` живёт в контейнере на Oracle (sqlite внутри нет):

```sh
ssh oracle 'docker cp hl-paper-scanner:/app/data/history_archive.json /tmp/ha.json'
scp oracle:/tmp/ha.json .
```

Выборка везде: `strategy_id='adopt' AND mode='PRODUCTION'` = реальные дискреционные входы.

## Скрипты

- **`recalc.py`** — вычитание хвостов. Net/exp/медиана по срезам (всё / минус ТОП-4 /
  минус бан-4 / тело), по сторонам, по бакетам холда; bootstrap-CI на экспектанси;
  per-coin таблица; концентрация (топ-N и низ-N сделок).
- **`stopsim.py`** — симуляция жёсткого стопа на фактических `mae_pct`: сделка выбивается
  ⟺ её просадка реально дошла до уровня. Плюс проверка «пик > просадки» против монетки
  и распределение результатов в %.

Оба ждут `ha.json` в рабочей директории:

```sh
python3 recalc.py
python3 stopsim.py
```

## Грабли

- `realized_pnl` — **net** (после fee-бэкфилла 26.06), а `pnl_pct` из цен — **gross**;
  в `stopsim.py` комиссия за круг добавляется вручную (`FEE_PCT = 0.09`).
- У ~100 из 400 сделок нет `mfe_pct`/`mae_pct`, и эта подвыборка смещена в минус
  (−0.10% против +0.16% на полной) — учитывать при чтении симуляции стопа.
- `entry_hour_utc` / `entry_trend_1h` у adopt не пишутся (входы приходят с биржи без
  снапшота) → оси «час» и «фейд/следуй» из этих данных не вытащить.
- Главное: **sd одной сделки 2.79% при среднем +0.16%** — на n≈400 любая нарезка даёт
  красивую подвыборку. Прежде чем радоваться срезу, прогоняй его без ТОП-4 монет
  и смотри bootstrap-CI.
